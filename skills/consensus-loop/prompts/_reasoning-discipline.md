# Reasoning discipline contract

This render-time prompt contract is prompt-level guidance only: not a runtime API, not a daemon, not a CLI, not a parsed schema field, not marker data, not lifecycle authority, and not a second transcript channel. It does not add or change terminal markers, worker output frontmatter, truth tables, solver or reviewer triplets, artifact profiles, GitHub authority, clean-exit handling, or lifecycle ownership.

Reference-frame: identify the applicable mature theory, engineering principle, industry best practice, mature industry case, mature pattern, or constraint framework governing this class of design, arbitration, or review; surface the known-good shape; then re-check each candidate conclusion, plan, implementation interpretation, repair candidate, approval path, abstain path, or converge path against it before settling the verdict. `no applicable mature theory found` is an acceptable explicit fallback; in that case the note says so and still records the root-cause and minimal-path re-check against the work-unit goal.

Aesthetic/adversarial: for each candidate approach weighed, including the chosen, revised, rejected, deletion/collapse, approval, comment, reject, repair, abstain, or converge approach, state why the approach is ugly as a specific locatable defect and what the beautiful form would be. Use `Ugly defect:` and `Beautiful form:` labels. Ugly defects include leaked abstraction, duplicated source of truth, special-case, bad coupling, asymmetry, lying name, hidden intent, or unverifiable premise. The beautiful form is the smaller, symmetric, single-responsibility, single-source-of-truth, intent-revealing form that satisfies the work-unit or PR goal.

seek truth from facts: verify every factual premise against actual evidence before relying on it. Evidence examples include source artifact or line, current file contents, command result, test assertion, visible input, implementation summary, solver output, reviewer output, issue body/comment, PR diff, or declared work-unit/PR constraint. Any assumed-not-verified premise must be explicitly marked `ASSUMED-UNVERIFIED:<premise>` in the existing artifact section, reasoning trace, evidence section, what-would-change-verdict item, convergence question, or GitHub post body when applicable; then verify it before routing, treat it as a goal gap/convergence question/what-would-change-verdict item, or abstain/reject/comment. Never silently rely on an assumed premise.

Surface one compact free-form reasoning-discipline note in the existing artifact or GitHub-post prose. The note names the reference frame, states the known-good shape and alignment/deviation/revision status, states the ugly defect and beautiful form for each candidate weighed, and states the verified-premise or `ASSUMED-UNVERIFIED` status needed for the verdict. It is not mandatory citation work, not a literature search, not a parsed schema field, not marker data, not lifecycle authority, and not a blocker for valid abstain, converge, reject, comment, or false-positive outcomes.
